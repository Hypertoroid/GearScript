Documentation

Describe how parts relate. GearScript works out the motion.

GearScript is a small, CSS-like language for mechanism animations. You write three short files, and the studio solves the joints, gears and cameras, renders every frame and exports a GIF.

At a glance

A script for machines: describe the parts and how they connect, drive one of them, and the rest follow.

The whole language follows three rules:

  1. A part declares what it connects to, inside its own block: attach, hinge, slider, mesh, couple, belt, pin.
  2. Units decide what a value means. 90deg is an angle, 90deg/s a spin rate, 90deg/s2 an angular acceleration. The same goes for mm, mm/s and mm/s2.
  3. Values come first, then keywords: rotate: 60deg/s about G1.axis; · orbit: Sun 30deg/s; · follow: Car offset (…);
// .scene: what exists let wheel = 55mm; Car::Group { body: Box { size: (440mm, 50mm, 180mm); } axle: Rod { length: 230mm; orient: 90deg about x; at: body.face.bottom; } } FL::Wheel { radius: wheel; hinge: axis on Car.axle.end.b; } Observer { position: (380mm, 330mm, 1150mm); }
// .style: how it looks Car { color: #2f6f8f; outline: 1px #13303d; } Wheel { color: gradient(#141619, #b9c0c8, axis: x); label: "front left"; }
// .motion: how it moves Car { 0s..2s: move: (0, 0, 0) -> (600mm/s, 0, 0) ease-in; } // speed up: a change of speed FL { forever: roll: Road; } // spin follows the distance travelled Observer { forever: follow: Car offset (380mm, 260mm, 1150mm); }

Getting started

A project is three files. Each one has a single job, like HTML, CSS and animations on the web.

FileAnswersContains
.sceneWhat exists?Parts, groups, anchors, connections, the camera and lights
.styleHow does it look?Selectors with colour, material, outline, opacity and labels
.motionHow does it move?Time blocks that drive parts, joints and the camera

Three files or one file

The same project can also be one file, with a line @scene, @style or @motion starting each section. Switch with the Three files / One file buttons in the header (or in Settings). Three files keeps three tabs and saves them as a .zip; One file is one .gscript file. The combined file is easiest to read top to bottom, and to hand to an AI assistant for review or edits.

@gearscript 1 @scene Crank::Link { length: 40mm; hinge: end.a on (0, 0, 0); } @style Crank { color: #b8442e; } @motion Crank { forever: rotate: 180deg/s; }
  • The first line, @gearscript 1, says which version of the language the project is written in. It is optional, and the studio writes it for you. Language 1 is stable: a project that works today keeps working in every 1.x release, and error codes keep their meaning.
  • Problems show the line in the single file and which section it is in; clicking one jumps there. Ctrl 1 / 2 / 3 jump to a section.
  • Pasting a single-file project into the three-file view fills all three tabs, so an assistant's one-block reply drops straight in.
  • In the single-file view, Save project writes project.gscript; Open reads .gscript files in either view.
  • Each marker sits alone on its line and each section appears once (E0105–E0107 explain any mix-ups; parts written before any marker, or straight under @common or a chapter line, are read as the scene with W0148, and Fix adds the missing @scene line). You cannot switch back to three files until the markers are fixed, so nothing is lost.

Only the parts that drive a mechanism need motion rules. Anything attached, hinged, meshed, coupled or belted to a driver follows by itself.

Your first animation: a swinging sign

Four steps build a shop sign that swings in the wind. Each step adds a few lines.

  1. Make a post and an arm. The arm's left face is aligned to a point near the top of the post's right face, so you never compute its centre.

    Post::Box { size: (40mm, 600mm, 40mm); at: (0, 300mm, 0); } Arm::Box { size: (300mm, 30mm, 30mm); align: face.left; at: Post.face.right + (0, 270mm, 0); }

  2. Hang the sign on a hinge. hinge: edge.top on Arm.edge.bottom; snaps the sign's top edge to the arm's bottom edge and lets it turn about that line.

    Sign::Box { size: (220mm, 140mm, 10mm); hinge: edge.top on Arm.edge.bottom; } Observer { position: (700mm, 520mm, 900mm); look-at: (120mm, 460mm, 0); } Light { kind: directional; direction: (-0.6, -1, -0.8); power: 0.85; } Scene { duration: 2s; }

  3. Give it a look. Styles use selectors: a type, a name, a .class or an #id.

    Post, Arm { color: #3b4148; material: metal; } Sign { color: #e0a63a; outline: 1px #5a3f0c; label: "Open"; }

  4. Make it swing. On a hinged part, rotate turns it about its hinge. Here the angle is a function of time t.

    Sign { forever: rotate: 20deg * sin(t * 3.1416); }

Ten minutes: from one crank to a finished video

Five steps take a four-bar linkage from one moving part to a lit, ticking animation you can export or send as a link. Each step only adds lines.

  1. Drive one part. A hinge at the origin and one motion rule. Nothing else moves by itself in GearScript: parts move because they are driven or connected.

    let crank = 40mm; Crank::Link { length: crank; width: 14mm; hinge: end.a on (0, 0, 0); }
    Crank { forever: rotate: 180deg/s; }

  2. Close a loop. The coupler hangs on the crank, the rocker on a fixed point, and a pin joins their free ends. You never say how the coupler or rocker move: the solver keeps the pin together at every instant.

    Coupler::Link { length: 120mm; width: 14mm; hinge: end.a on Crank.end.b + (0, 0, 6mm); anchor tip: (10mm, 46mm, 0); pin: end.b to Rocker.end.b; } Rocker::Link { length: 90mm; width: 14mm; orient: 90deg about z; hinge: end.a on (110mm, 0, 0); }

  3. Trace a curve. The coupler names a point of its own, tip. Attach a small sphere there and give it a trail: it draws the coupler curve, the shape engineers use to design walking machines.

    Pen::Sphere { radius: 5mm; attach: Coupler.tip; }
    Pen { color: #ffd27a; trail: #ffb84d; }

  4. Light and sound. luminosity makes the pen glow and light what is near it; a generated click marks each turn of the crank (one turn takes 2 s at 180°/s).

    Click::Sound { kind: click; } Scene { duration: 4s; background: #0f1216; }
    Pen { color: #ffd27a; luminosity: 80%; trail: #ffb84d; }
    Crank { forever: rotate: 180deg/s; sound: Click every 2s; }

  5. Tidy, check and share. Press Shift Alt F to beautify the code. The Problems list should say "No problems". Then Export › MP4 for a video with sound, or Save › GearScript file to send the project itself: whoever opens the file gets the whole project, every chapter included.

Expressions

Arithmetic (+ - * /) and these functions work anywhere a number does: sin cos tan sqrt abs min max pow floor exp atan2 length. PI is π.

// A point on a circle of radius 140mm, 250 degrees round Earth::Sphere { radius: 10mm; at: (140mm * cos(250deg), 0, 140mm * sin(250deg)); }

let: named values

let names a value once and works in all three files. Names start with a lower-case letter, because capitals are reserved for parts. A let can hold a number, a vector or a whole expression, even one that uses a curve's u.

let cruise = (600mm/s, 0, 0); let year = 12s; Car { 0s..2s: move: (0, 0, 0) -> cruise; } Earth { forever: orbit: Sun 360deg / year; }

Reserved names: t i u v x y z axis to on at about step offset.

Comments

// to the end of the line and /* blocks */, as in CSS. # is never a comment: a # followed directly by letters or digits is a colour (#38bdf8) or an id (#G2), and a # followed by a space is error E0104.

Parts and groups

Every part is declared as Name::Type, with optional classes, and a block of properties. Names start with a capital letter.

G1::Gear.gear.steel { teeth: 36; module: 2mm; width: 10mm; at: (0, 0, 0); }

Groups

A Group holds named members that share one frame. Members can be placed against each other, and the group moves as one.

Door::Group.wooden { panel: Box { size: (800mm, 2000mm, 40mm); } knob: Sphere { radius: 30mm; at: panel.face.front + (320mm, 0, 25mm); } anchor grip: knob.center; // a custom anchor on the group at: (430mm, 1000mm, 0); }

Refer to a member as Door.knob, and to its anchors as Door.panel.edge.left.

repeat and i

repeat: N makes N copies named Name1 to NameN. Add step (dx, dy, dz) to shift each copy, or use i (0, 1, 2 …) in any expression for patterns such as rings.

// A row of lane dashes: Road.dash1 ... Road.dash11, 500mm apart Road::Group { surface: Box { size: (6000mm, 4mm, 700mm); } dash: Box.dash { size: (220mm, 2mm, 18mm); at: surface.face.top + (-2500mm, 1mm, 0); repeat: 11 step (500mm, 0, 0); } } // A ring of 7 trees Trunk::Cylinder.trunk { radius: 9mm; height: 70mm; repeat: 7; at: (680mm * cos(i * 0.9), 35mm, 620mm * sin(i * 0.9)); }

Give repeated parts a class (.dash, .trunk) and style or move them all with one selector.

scatter: random copies

scatter places copies at random spots that stay the same every time you build: leaves on a floor, droplets in a cloud, stars in a field. Choose the area, then any options.

Leaf::Polygon.leaf { sides: 5; radius: 22mm; thickness: 2mm; scatter: 40 in plane xz (640mm, 440mm) seed 4 spin 360deg vary 30% apart; } Drop::Sphere.drop { radius: 8mm; at: (0, 200mm, 0); scatter: 25 in sphere 120mm; } Peg::Cylinder.peg { radius: 6mm; height: 40mm; scatter: 12 on circle 300mm; }

Areas: in plane xz (w, d) (also xy, yz, any plane as an equation in quotes, in plane "x + y + z = 300mm" (w, d), or in plane normal (1, 1, 0) (w, d) through the part's at), along x 800mm, in box (x, y, z), in disc 300mm, on circle 300mm, in sphere 200mm. Options: seed 7 for another layout, spin 360deg for a random turn, vary 20% for different sizes, apart to keep copies from touching. Flat shapes lie down in the plane; give a plane a third size, in plane xz (600mm, 400mm, 200mm), and the copies also spread 200 mm off it, filling a slab (bubbles, dust, stars) instead of lying flat. The copies are Leaf1 … Leaf40; style and move them all through their class.

fixed: a place on the screen

When the Observer moves, orbits or follows a part, a title in the scene drifts away. fixed pins a part to the screen instead: it stays at that place, at the size it has from the Observer's starting point, whatever the camera does. It keeps its own motion, so a badge can still spin and a caption can still fade.

Title::Text { text: "How a gearbox works"; size: 16mm; fixed: top-left; } Logo::Polygon { sides: 6; radius: 14mm; thickness: 3mm; fixed: bottom-right 4%; } Step::Text { text: "Step 2"; fixed: (50%, 90%); }

Places: top-left, top, top-right, left, center, right, bottom-left, bottom, bottom-right, then an optional margin written as a bare percentage, fixed: bottom-right 4%; (5% of the frame's height by default; there is no margin word or property, and W0232 offers to fix either); or (x%, y%) for the part's centre from the top-left corner. A fixed part goes on a whole part, not a group member, and takes no hinge, attach or other connection.

Stacking: parts at the same named place that show at the same time stack instead of covering each other: a title and a subtitle both at fixed: top; sit one under the other; at the bottom they stack upwards. A part that has faded out (opacity 0) leaves its place free, so captions that take turns still sit in one spot.

caption-band: a clear strip for words

Words on top of a moving mechanism are hard to read and hide what they describe. caption-band keeps a strip at the bottom of the picture clear: the scene is drawn smaller, above it. Captions from narration sit at the bottom of the band, and Texts with fixed: band; at its top.

Scene { frame: youtube; caption-band: 18%; } Note::Text { text: "Teeth push on teeth"; size: 6mm; fixed: band; }

The band runs from 0 to 40% of the height; on is 18%, off removes it. It shapes the Observer's view, in the preview and in exports; the Free camera ignores it.

define: your own part types

define names a part type built on a shape or a group, with parameters and optional defaults. Use it like a built-in shape, with values in brackets, by position or by name. Properties in the part's own block are added to the type's, and replace any with the same name.

define Tyre(mount, r = 55mm) :: Wheel { radius: r; width: 34mm; hinge: axis on mount; } FL::Tyre(Car.axle1.end.b); FR::Tyre(Car.axle1.end.a); RL::Tyre(mount: Car.axle2.end.b, r: 60mm);

The type's name is also a selector and a motion target, so one rule styles or moves every part built from it:

Tyre { color: gradient(#16181b, #5d6670, axis: x); }
Tyre { forever: roll: Road; }

A parameter can hold any value, including an anchor such as Car.axle1.end.b. Parameters hide let values with the same name. A type built on a Group cannot go inside another group.

Your own 3D models

More › 3D models… adds STL, GLB or glTF files (a glTF must be a single file; export as .glb if it points to others). Each file is placed with a Mesh part, which fits the model inside its size box: fit: contain (the default) keeps its proportions, fit: stretch fills the box. Because the box is known, every Box anchor works, so models attach, hinge and slide like any other part. Adding one model inserts a Mesh line for you, sized from the file (read as millimetres). Models are saved inside the project's .zip and kept in this browser.

Piston::Mesh { src: "piston.stl"; size: (60mm, 90mm, 60mm); at: (0, 45mm, 0); }

Curves: shapes as functions

A Curve is any function of a parameter. Use t inside it and the curve changes over time.

Wave::Curve { domain: u in 0..1; point: (u * 400mm - 200mm, 40mm * sin(6.283 * (u * 2 - t / 2s)), 0); stroke: 4mm; }

attach

Moves the part so its anchor sits on the other part's anchor, then fuses them. With one anchor, the part's centre is used.

hinge and slider

Both take own line on other line, or just the other line (then the part's own axis is used). The other side can also be a point: an anchor plus an offset, or a fixed position such as (110mm, 0, 0). Then the part turns about its own line through that point. The part's motion rule drives the joint. Add range to limit it. A group can be hinged too: name a member's line as its own line.

Sign::Box { size: (220mm, 140mm, 10mm); hinge: edge.top on Arm.edge.bottom; range: -30deg..30deg; } FL::Wheel { radius: 53mm; width: 34mm; hinge: axis on Car.axleF.end.b; } Piston::Cylinder { radius: 36mm; height: 50mm; slider: axis on Barrel.axis; range: -110mm..110mm; } Door::Group { panel: Box { size: (800mm, 2000mm, 40mm); } hinge: panel.edge.left on Frame.edge.right; }

Hinges carry their part along when the part they sit on moves. That is how wheels ride on a car and a forearm rides on an upper arm.

mesh, couple and belt

mesh places the gear at the correct centre distance, turns it so the teeth interlock and sets the ratio. Add at 60deg to place it round the other gear. couple uses any ratio between round parts. belt draws a belt and turns both pulleys the same way.

G1::Gear { teeth: 36; module: 2mm; at: (0, 0, 0); } G2::Gear { teeth: 12; module: 2mm; mesh: G1; } // turns -3 times as fast G3::Gear { teeth: 18; module: 2mm; mesh: G2 at 60deg; } // placed above G2

Linkages and closed loops

Hinges in a chain are easy: each part rides on the one before. A closed loop, where the chain comes back to the ground, also needs the parts to stay together. pin says which two points must meet. Drive one joint, such as the crank. Every hinge or slider in the loop without a motion rule is solved at each frame so the pins hold.

// A crank-rocker four-bar linkage Crank::Link { length: 40mm; hinge: end.a on (0, 0, 0); } Coupler::Link { length: 120mm; hinge: end.a on Crank.end.b + (0, 0, 6mm); pin: end.b to Rocker.end.b; } Rocker::Link { length: 90mm; orient: 90deg about z; hinge: end.a on (110mm, 0, 0); }
Crank { forever: rotate: 180deg/s; }

Slider-crank

The same idea with a slider. The piston has no motion rule, so it slides to wherever the connecting rod puts it.

Crank::Link { length: 50mm; hinge: end.a on (0, 0, 0); } Bore::Cylinder { radius: 22mm; height: 220mm; orient: 90deg about z; at: (200mm, 0, 0); } Piston::Cylinder { radius: 20mm; height: 40mm; slider: axis on Bore.axis; } Rod::Link { length: 180mm; hinge: end.a on Crank.end.b + (0, 0, 6mm); pin: end.b to Piston.center; }
  • Use Link for bars. Its ends are lines along z, so hinges and pins on them turn in the xy plane.
  • A pin is an axle. Parts can sit at different depths along it, which is why + (0, 0, 6mm) layers the coupler in front of the crank.
  • The starting pose picks the branch. A four-bar can usually close two ways, elbow up or down. Orient the rocker roughly where you want it.
  • The compiler checks the whole motion. E0352 means the loop cannot close at all; check the lengths. E0353 gives the time when the linkage locks, for example when a crank is too long to turn fully.

Cutaway and exploded views

Explainers often need to show what is inside. Three tools do it without changing the parts themselves.

Cut a part open

Barrel { cut: z 0mm; cut-color: #b8442e; } // cuts away the half towards the viewer Cover { cut: -x 40mm; } // cuts away everything left of x = 40mm

cut is a direction and an offset: a flat plane in scene coordinates, and the side the direction points to is removed. z points at the viewer, so cut: z 0mm; opens the front half. Use x, -x, y, -y, z, -z or a vector such as (1, 0, 1). The cut faces are filled in a darker shade of the part's colour, or cut-color. The plane stays where it is while the part moves, like a real section. cut: none; removes a cut set by an earlier rule.

Barrel, Gland { 0s..1.5s: cut: 90mm -> 0mm ease-out; } // the plane slides in

In motion, cut moves the plane: an offset, or a change from one offset to another. It takes its direction from the style (or z if the style has none). A cut never moves a part, so it can sit beside any motion source.

See through a casing

Housing { material: ghost; } // faint faces, clear edges Housing { material: ghost; opacity: 0.3; } // a little more solid

Explode an assembly

Scene { explode: 1 along y; } // a still exploded view
Scene { 1s..3s: explode: 0 -> 1.2 ease-in-out; } // the parts move apart, then stay apart
Base { explode: 0; } // stays where it is Bolts { explode: 2; } // moves twice as far as the rest

Each part moves away from the middle of the model by its distance from the middle times the amount: at 1, every part is twice as far out. along x, y or z keeps the movement to one axis, which suits stacks such as a gearbox cover and back plate. Parts held together by a group move as one; Text and Plot parts stay put unless they have their own explode weight. The exploded positions are for showing: hinges, meshes and the camera still follow the assembled positions.

Acceleration

There is no separate acceleration keyword: write the unit and the value means it. Three common patterns:

// 1. Speed up, cruise, brake: changes between speeds let cruise = (600mm/s, 0, 0); Car { 0s..1.5s: move: (0, 0, 0) -> cruise ease-in; then: move: cruise; 3s..4.2s: move: cruise -> (0, 0, 0) ease-out; } // 2. A thrown ball: a launch speed plus gravity, both as move lines Ball { 0s..1.5s: move: (600mm/s, 1200mm/s, 0); move: (0, -1.62m/s2, 0); } // 3. A motor spinning up: an angular acceleration, then a steady speed Motor { 0s..1s: rotate: 360deg/s2; then 3s: rotate: 360deg/s; }

roll

roll turns a hinged wheel by the distance its centre travels divided by its radius, so the spin always matches the speed, including while speeding up and braking. It assumes straight-line travel on level ground.

orbit

orbit keeps a part's offset from a centre part and swings it round. Because the centre is followed, orbits nest: a moon can circle a planet that circles a star.

Earth { forever: orbit: Sun 360deg / 12s; rotate: 360deg / 2s; } Moon { forever: orbit: Earth 360deg / 2s; }

Words are part of the scene, drawn in 3D, so they sit where you put them and never cover the motion. There are two kinds: a Text part, made only of words, and face text, printed on any part's faces.

Sky, ground and sun

Scene { duration: 8s; sky: dusk; ground: #2c3328; sun: (6deg, -30deg) #ffb36b; }
Scene { 0s..8s: sun: -5deg -> 10deg ease-in-out; } // a sunrise

sun draws a sun on the sky: its height above the horizon, then its direction (0deg looks into the scene along −z, 90deg is to the right, along +x), then an optional colour. It sits far beyond the scene, so it never rests on the ground; below the horizon it is hidden, and it lights the scene from where it stands, fading as it sets. Animate its height in a Scene motion rule for a sunrise or a sunset.

The ground sits at the foot of the model (glowing parts do not count, so a lamp below it stays hidden); ground: #2c3328 at 0mm; sets the height yourself. shadow: none; in a part's style stops it casting a shadow.

sky wraps the whole scene in a hollow, glowing sphere that travels with the camera, so you never reach its edge. Choose a preset, day dawn dusk sunset night space overcast studio, or give one to three colours from the top through the horizon to below: sky: #1d3b70 #f2b38a #2a2030;. Narration and voice-overs

Narrator::Voice { voice: en-GB; rate: 95%; }
Crank { 0s..3s: rotate: 0deg -> 180deg; say: Narrator "The crank turns half a revolution."; }

say speaks a line with the browser's own voice, in the studio and in the 3D player, and shows it as a caption. voice is a language such as en-US or en-IN, or the name of a voice on the computer (the hints list them); captions: off; speaks without the words. A video file cannot record the browser's voice, so exports draw the captions into the picture, and the export panel saves them as an .srt file for YouTube or a video editor. For speech in the file, keep Speak them into the video ticked in the export panel (it is, by default): a neural voice (Piper) runs in your browser and speaks each line into the MP4 or WebM. It is experimental, and the voice (20 to 70 MB) downloads the first time; neural: en_GB-alan-medium; on the Voice picks one. Or record a voice-over, or make one with any text-to-speech tool, and add it with Insert › 3D models and audio, and play it like any sound:

Writing lines that land: a voice speaks about 2.6 words a second at rate: 100%. Leave that long before the next line of the same voice, because a new line cuts the caption off, and make the block or Scene { duration } long enough for the last line to finish. One idea per line, 4 to 14 words, works best. Put a line in the block whose motion it describes, so words and motion move together when you change the timing.

Captions like subtitles: a long line is not shown all at once. It is split into parts of at most two short lines, at sentence ends first, then at commas, then between words, and each part shows for its share of the time the line takes to say. The same parts go into exports and caption files. Still, a paragraph in one say: reads badly and cannot follow the picture: W0551 warns about a line over 40 words, and W0550 when a line is still being spoken as the next one starts.

Captions as files: the export panel saves every caption part as .srt (YouTube, video editors) or .vtt (web players: <track src="name.vtt">). With chapters, the times run across the whole film.

Audio files (MP3, WAV, OGG, M4A) also work for music and recorded effects. They play in the preview, are mixed into MP4 and WebM, and are saved in the project's .zip.

Chapters

A longer video is easier to make in parts. Each chapter is a complete animation, with its own time starting at 0 s and any length, and the export joins them into one video. You can preview, fix and export any chapter on its own.

  • Start: press Chapters in the bar above the code. What you have becomes Chapter1, and Chapter2 continues it with the same scene and style, ready for new motion.
  • The strip above the code shows common and every chapter as a timeline: each block is as wide as the chapter is long (within limits), with its length, a mark for a fade or crossfade, and a progress line while the film plays. Drag a block to move the chapter. Click one to edit it; double-click (or ⋯) for its settings: name, title, what it starts from, how it starts, and a fade-out at the end. The × on a chapter deletes it: an empty one goes at once, one with code asks first (Shift-click skips the question), and Undo in the note that follows brings it back. + adds a chapter that continues this one, a copy, or a blank one. Right-click a chapter to move, duplicate or delete it.
  • Film, under the preview, plays every chapter in order with its transitions, as the export will. It is the default (the studio remembers if you pick Chapter), and clicking a chapter while the film plays moves the film to that chapter. Chapter plays only the one you are editing. The tracks panel shows the chapters as a row along the top while the film plays.
  • Problems lists errors in every chapter, marked with the chapter's name; click one to go there.
  • Pasting a reply: a reply with chapters is merged by chapter name. A chapter with a name you have replaces yours, a new name is added, and chapters the reply leaves out stay as they are; @common changes only when the reply has one. When a paste would change more than one of your chapters, a dialog lists them first, so you can untick any you want to keep. One Undo puts it all back. To change just one chapter with an AI, use Prompt AI › Ask about: This chapter.

In the code

@gearscript 1 @common @scene Scene { frame: youtube; sky: studio; } // every chapter shares the picture Narrator::Voice { voice: en-GB; } @style Gear { color: brass; material: metal; } @chapter Intro "Two gears" fade 0.8s @scene G1::Gear { teeth: 36; } G2::Gear { teeth: 12; mesh: G1; } @motion G1 { 0s..4s: rotate: 0deg/s -> 40deg/s; say: Narrator "Two gears, one driving the other."; } @chapter Ratio extends Intro crossfade 1s fade-out 1s @scene Observer { position: (0, 60mm, 420mm); look-at: G2; } // replaces the camera it inherits @motion G1 { forever: rotate: 40deg/s; }
On a chapter lineDoes
@chapter Namestarts a chapter; the name starts with a capital letter. Its @scene, @style and @motion follow (leave out any it does not need)
"Title"the title used in the chapter list for a video description (the name, spaced out, if left out)
extends Otherstarts from Other's scene and style, not its motion. Add parts and later style rules; a new Observer replaces the one it inherits
cut · fade 0.8s #000000 · crossfade 1show this chapter starts: straight in, through a colour, or blended over the end of the chapter before (a crossfade overlaps the two)
fade-out 1sfades to black (or a colour) at the end: for the last chapter

@common comes first and holds what every chapter shares: put Scene { frame: … } there, since one video has one shape. Chapters save as one .gscript file (or a .zip with 3D models), and the 3D player carries every chapter.

The preview shows a crossfade with a still picture of the chapter before; the export blends the moving pictures.

Export and projects

  • Whole film or this chapter: with chapters, the export panel asks which. MP4 and WebM exports run to 20 minutes at 30 fps (longer at a lower frame rate); GIFs are for short clips.
  • Chapter list: with chapters, Copy the chapter list gives lines such as 0:00 What a gearbox does for a YouTube description (YouTube makes chapters when there are at least three, each 10 s or longer).
  • Tracks (the button at the right of the timeline) shows every motion rule, spoken line and sound on a time axis. Click a bar to jump to that moment and to its line in the code.
  • Export has five formats; MP4 and WebM carry the project's sounds. If you change the code or an export option after rendering, Save is switched off until you render again, so a saved file always matches what you see. Long animations export their first part at true speed (a GIF holds 300 frames; a video 3,600), and the panel says how much fits. MP4 (H.264, plays everywhere) and WebM (VP9, small) videos: 640 to 1920 px wide, 24, 30 or 60 fps, three quality levels, up to 3,600 frames. GIF: 320 to 800 px, 15 to 25 fps, up to 300 frames; it has only 256 colours, so videos look smoother. PNG frames: every frame as a numbered PNG in one .zip (up to 1,800 frames), with full transparency; video editors (Premiere, DaVinci Resolve, After Effects, Final Cut) import it as an image sequence. With a transparent background a GIF keeps it too, with each pixel fully clear or solid. 3D player: one .html file with the animation inside; anyone can open it in a browser to watch, pause, scrub, orbit with Free and change what is shown from the right-click menu, and it can be put on any website or embedded with an <iframe>. Pick the shape for videos and GIFs: like the preview, 16:9, 1:1, 4:5 or 9:16. Exports always use the Observer camera. Video needs a current Chrome, Edge, Safari or Firefox.
  • Shadows: the main light casts soft shadows, including onto the ground under the model. Turn them off in Settings or the right-click menu if the preview is slow.
  • No accounts: there is nothing to sign up for. Everything, including every export, works straight away, and your projects stay in your browser. Where the studio runs on a GearScript server, it asks once whether it may count which features are used; a copy opened on its own asks nothing and sends nothing.
  • File menu: New project (Ctrl Alt N) starts from a blank page or a starting point: a Short or Reel, an explainer, an assembly sequence or a slide graphic. Open recent lists the last eight projects in this browser (the code; 3D models and audio files are added again). One-file projects save as .gscript; the installed Studio opens .gscript files from your computer.
  • Project name: the bar above the code shows it. Click it to rename. An orange dot means there are unsaved changes.
  • Save (the button in the header, or Ctrl S) uses the project name. Its arrow (or Ctrl Shift S) saves as an .gscript file, a .zip, three loose files (into a folder you pick, in Chrome and Edge) or JSON for other tools. In Chrome and Edge the first save asks where to put the file, and later saves write straight back to it, like a desktop app; other browsers download a copy each time. Before an example or another project replaces unsaved work, and before you close the tab, the studio asks whether to save.
  • By default, Save in the One file view writes name.gscript; in the Three files view it writes name.zip holding name.scene, name.style and name.motion. Open reads either (and .json projects saved for tools), takes the project name from the file name and switches to the matching view.
  • Is the preview up to date? The small badge at the top left of the preview tells you: a blue spinner while your latest edits are waiting to run, a green tick once the preview shows them, and a red mark when the code has errors (the preview then keeps the last version that compiled).
  • Right-click the preview (or press the Menu key or Shift F10 on it) for play and restart, speed, show or hide labels, the floor grid, joint axes, trails and the scene summary, the background, the camera (with Reset the view, also the circular-arrow button above the preview, which brings a Free camera back to where the scene's Observer stands), expand, save the current frame as a PNG and export a GIF. Changes there are saved to Settings, and Settings changes show there.
  • Examples and new projects open in this tab; with unsaved work the studio asks first and offers a new tab instead.
  • Download Studio (in the More menu) installs GearScript Studio as an app, the same way Chrome and Edge offer with the install icon in the address bar: it gets its own window and icon, and works offline. Where the browser cannot install (Firefox, or a page shown inside another site), the dialog explains what to do, and offers the whole studio as one HTML file that opens from disk with no internet.
  • After you save an export, a small note may ask whether you would like to say thanks (a coffee, a star, or sharing the link). It shows after the first save and then now and again, and never again once you tick Don’t show this again or use one of its links.
  • Your edits are kept in this browser between visits.

Command line and AI agents

The cli folder in the download has a command-line tool. It reads the compiler straight out of studio.html, so it can never disagree with the studio. It needs Node 18 or later: run npm install in the folder once.

The Prompt AI button

In the studio, Prompt AI copies a short version of the syntax as instructions any chat assistant can follow. The reply format follows your view: in the three-file view it asks for three code blocks (scene, style, motion); in the one-file view, for a single block with @scene, @style and @motion sections, so the reply pastes straight back. The panel shows which format it will ask for and lets you switch. Type what you want to animate, tick Include my current code if it should edit your project, and paste the result into the assistant. It replies with three code blocks: paste each into its tab. node gearscript.js prompt prints the same text (add --single for the one-file format).

The dialog can add your current code, the problems (ticked when there are any, so the AI fixes them first), and where every part is at the current time. The prompt carries the rules for narration and chapters only when your request or your code uses them, and ends with a short checklist of the slips AI replies make most. In a project with chapters, Ask about: This chapter sends @common and the chapter on screen only, and asks for that chapter back; the reply is merged by chapter name, so the others stay as they are.

AI on this site

Where the studio runs with a GearScript server that has an AI key, the AI panel also has Generate: it sends the same prompt to the AI and puts the answer straight into the editor, and Undo the AI change puts your project back. When the code has errors, Fix with AI appears in the Problems panel and sends the errors with the code. Each visitor has a daily number of requests. Without the server, Copy prompt works with any assistant.

Using GearScript from an AI agent

  1. Give the agent SPEC.md: the whole language on a few pages.
  2. Connect the MCP server, or let the agent run the command-line tool.
  3. The agent writes the files, calls check until there are no errors, calls sample to confirm the motion, then render.

The evals folder holds 16 tasks with prompts, numeric checks and reference answers. Use it to measure how often a model gets a mechanism right first time.

Current limits

What language 1 does not do, so you know before you start:

  • No forces or collisions. Motion is described, not simulated: there is no mass, gravity unless you write it, bouncing or friction.
  • Accelerations are constant within a block. Use several blocks, or a change between speeds, for anything else.
  • Loops are solved, not simulated. Linkages with pins work, including four-bars and slider-cranks. Ball joints, cams and gears inside a loop do not yet.
  • roll assumes straight-line travel on level ground.
  • Solid functions (signed-distance solids) and boolean operations are not in yet. Curves are.
  • Motion rules move whole parts, not individual group members. Use a hinge or a separate part instead.
  • Rendering is clean and simple: soft shadows, metals, glass and light from luminous parts, but no image textures.
  • Exploded views are for showing: joints and the camera follow the assembled positions, and trails do not explode.
  • Overlap warnings are sampled at up to 24 moments, so a very fast pass-through between samples can be missed.
